# 📊 E-commerce Data Mart Pipeline (Apache Airflow)

Этот проект представляет собой автоматизированный ETL-пайплайн (Extract, Transform, Load), оркестрируемый с помощью **Apache Airflow**. Пайплайн предназначен для сбора, очистки и загрузки данных интернет-магазина в аналитическое хранилище (DWH) с последующим построением витрин данных (Data Marts).

## 🎯 О проекте

Пайплайн решает задачу регулярного обновления аналитики продаж и удержания клиентов (Retention). Данные забираются из внешнего API инкрементально (только новые изменения за конкретную дату), что позволяет эффективно использовать ресурсы и не перегружать базу данных.

### 🗂 Архитектура DWH (Схема "Звезда")
Данные проходят через два слоя:
1. **Staging (Сырой слой):** `user_order_log` — временное хранилище для вновь поступивших данных.
2. **Mart (Аналитический слой):**
   * **Измерения (Dimensions):** `d_city` (города), `d_customer` (клиенты), `d_item` (товары).
   * **Факты (Facts):** 
     * `f_sales` — ежедневные продажи.
     * `f_customer_retention` — еженедельный расчет удержания клиентов (разделение на новых и вернувшихся, расчет выручки и возвратов).

## 🛠 Технологии и инструменты
* **Оркестрация:** Apache Airflow (DAGs, PythonOperator, PostgresOperator, XCom).
* **Язык программирования:** Python 3.
* **Библиотеки Python:** `requests` (работа с API), `pandas` (очистка данных).
* **СУБД:** PostgreSQL (загрузка через `SQLAlchemy` и выполнение SQL-скриптов).
* **Аналитика:** Продвинутый SQL (CTE, агрегации с `FILTER`, оконные функции).

## ⚙️ Логика работы DAG (`sales_mart`)

DAG запускается ежедневно (`@daily`) с включенным параметром `catchup=True`. Процесс состоит из следующих шагов:
1. **`generate_report`**: Отправка POST-запроса на генерацию отчета в API.
2. **`get_report`**: Циклическая проверка статуса готовности отчета.
3. **`get_increment`**: Получение ID инкремента за конкретную дату (`{{ ds }}`).
4. **`upload_user_order_inc`**: Скачивание CSV-файла, его очистка с помощью Pandas (удаление дублей по `uniq_id`) и загрузка в `staging.user_order_log`.
5. **Обновление справочников (параллельно):** Выполнение SQL-скриптов для обновления таблиц `d_item`, `d_customer`, `d_city`.
6. **`update_f_sales`**: Добавление новых строк в таблицу фактов продаж.
7. **`update_f_customer_retention`**: Расчет метрик Retention. Сначала удаляются старые данные за текущую неделю, затем агрегируются новые (с расчетом новых клиентов, вернувшихся и суммы возвратов).

## 🚀 Как развернуть проект

1. Склонируйте репозиторий.
2. Убедитесь, что у вас развернут Apache Airflow с установленным провайдером PostgreSQL.
3. Настройте подключения (**Connections**) в интерфейсе Airflow:
   * `http_conn_id` — для доступа к API (с прописанным `api_key` в поле Extra).
   * `postgresql_de` — для доступа к вашей базе данных PostgreSQL.
4. **Настройка переменных окружения:**
   Для безопасности конфиденциальные данные (никнейм и когорта) не хранятся в коде. 
   Создайте в корне проекта файл `.env` на основе шаблона `.env.example` и заполните его своими данными:
   ```text
   PRACTICUM_NICKNAME=ваш_никнейм
   PRACTICUM_COHORT=ваша_когорта
